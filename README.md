# Stack-Based Expression Evaluator



A Python program that reads mathematical expressions from `input.txt`, evaluates each one using a **stack-based algorithm**, and writes the results to `output.txt` in the same layout as the input.

---

## 1. Project Files


 `stack_evaluator.py`  Main program: `Stack` class, tokenizer, evaluator, file input/output 
`input.txt`  Sample input file used for testing 
 `output.txt`  Output generated by the program from `input.txt` 
 `test_stack_evaluator.py`  30 automated unit tests (`unittest`) 
 `README.md`  This document 

## 2. Requirements

- Python **3.8 or newer**
- No external libraries (standard library only: `argparse`, `os`, `re`, `sys`, `unittest`)

Check your version:

```bash
python --version
```

## 3. How to Run

Open a terminal in the project folder and run:

```bash
python stack_evaluator.py
```

This reads `input.txt` and writes `output.txt` (both in the same folder as the script).

**Optional arguments**

```bash
python stack_evaluator.py my_input.txt my_output.txt   # use different file names
python stack_evaluator.py --verbose                    # also print each expression and result
python stack_evaluator.py --help                       # show usage help
```

Example console output with `--verbose`:

```
Expression                                   Result
------------------------------------------------------
3 + 5 * 2                                    13
(8 / 4) + 7 * 2                              16
10 - (2 + 3) * 4                             -10
...
Processed 10 expression(s): 8 evaluated, 2 error(s).
Results written to 'output.txt'.
```

> On some systems use `python3` instead of `python`.

## 4. How to Run the Tests

```bash
python -m unittest test_stack_evaluator.py -v
```

Expected result: `Ran 30 tests ... OK`

The tests cover: stack operations (push, pop, peek, is_empty, size, empty-stack errors), tokenizing, operator precedence, left-associativity, nested parentheses, decimals, unary minus, error handling, result formatting, separator detection and a full file read → evaluate → write round trip.

## 5. Input File Structure (`input.txt`)

- One expression per line.
- Expressions are separated by a **separator line** such as `-----`.
- Allowed in expressions: whole numbers, decimals, `+`, `-`, `*`, `/`, `(`, `)` and spaces.

```
3 + 5 * 2
-----
(8 / 4) + 7 * 2
-----
10 - (2 + 3) * 4
```

## 6. Output File Structure (`output.txt`)

- Same number of lines and same layout as the input.
- Each expression is replaced by its result; separator lines are copied unchanged.
- An invalid expression is replaced by `ERROR: <reason>` so the line positions still match the input.

```
13
-----
16
-----
-10
```

## 7. How It Works (Summary)

The evaluator uses **two stacks** (Dijkstra's Shunting-Yard approach):

1. **Operand stack** – holds numbers.
2. **Operator stack** – holds `+ - * /` and `(`.

Reading the expression left to right:

 Token  Action 
 Number  Push onto the operand stack 
 `(`  Push onto the operator stack 
 `)`  Apply operators until the matching `(` is found, then discard the `(` 
Operator  While the top operator has higher or equal precedence, apply it; then push the new operator 

At the end, all remaining operators are applied. The single value left on the operand stack is the result. **Applying** an operator means: pop two operands, compute, push the result back.

Precedence: `*` and `/` (level 2) before `+` and `-` (level 1); unary minus is level 3.

## 8. Assumptions

- A separator line is a line made of **three or more** repeated `-`, `=`, `_`, `~` or `#` characters. It is copied to the output exactly.
- Blank lines are kept as blank lines.
- `/` is true division (`7 / 2 = 3.5`), not integer division.
- Whole-number results are written without a decimal point (`16`, not `16.0`).
- Non-whole results are rounded to 6 decimal places with trailing zeros removed (`10 / 3` → `3.333333`).
- A `-` at the start of an expression, after `(` or after another operator is a **unary minus** (e.g. `-4 + 2`, `3 * -(2 + 1)`).
- Operators of equal precedence are evaluated left to right (`20 - 6 - 4 = 10`).

## 9. Error Handling

The program never crashes on a bad expression. It writes an error message on that line and continues with the rest of the file:

 Problem  Example  Output 

 Division by zero  `7 / 0`  `ERROR: Division by zero` 
 Missing `)`  `(3 + 4 * 2`  `ERROR: Mismatched parentheses: missing ')'` 
 Extra `)`  `3 + 4)`  `ERROR: Mismatched parentheses: unexpected ')'` 
 Missing operand  `3 +`  `ERROR: Operator '+' is missing an operand` 
 Missing operator `3 4`  `ERROR: Malformed expression (missing operator between values)` 
 Invalid character  `3 + a`  `ERROR: Invalid character 'a' at position 5` 

If `input.txt` does not exist, the program prints an error message and exits with status code 1.

## 10. Limitations

- Only the four operators `+ - * /` are supported (no `^`, `%`, functions such as `sqrt`, or variables).
- Implicit multiplication such as `2(3 + 4)` is not supported and is reported as an error.
- Floating-point arithmetic is subject to normal binary rounding; results are rounded to 6 decimal places for display.
